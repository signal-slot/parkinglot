# Parking Lot UI

A multi-platform parking lot management system with implementations for various frameworks and devices.

## Project Overview

This project provides parking lot management user interfaces implemented across multiple platforms and frameworks. It includes implementations for mobile (Flutter), desktop (Qt), and embedded systems (Raspberry Pi Pico with Slint UI).

All UI implementations were generated from a single PSD file (`コインパーキングUI.psd`) using the export tool included in the [qtpsd](https://github.com/signal-slot/qtpsd) repository.

The application simulates a parking lot management system with features like:
- Parking slot selection
- Payment processing
- Support for various payment methods (credit cards, IC cards like Suica, PASMO, etc.)

## Repository layout

The repo separates **design** (generated UI + scaled images) from **implementation** (logic + build glue) so that any implementation can be combined with any pre-exported resolution. The first axis is keyed by **export format** (qt, qt-nogpu, slint), not by impl — so `pico`, `pico2`, and the desktop Slint app all consume `design/slint/<resolution>/`.

```
design/<format>/<resolution>/  ← generated by qtpsd; do not hand-edit
  qt/{800x600,1024x600,1280x800,1920x1080}/
  qt-nogpu/{800x600,1024x600,1280x800,1920x1080}/
  slint/{320x240,800x600,1024x600,1280x800,1920x1080}/

<impl>/                        ← logic + build glue only (no symlinks, no copied design files)
  qt/main.qml + run.sh
  qt-nogpu/main.qml + run.sh
  slint/main.slint + run.sh
  pico/{src,ui,Cargo.toml,build.rs,...}
  pico2/{src,ui,Cargo.toml,build.rs,...}
  flutter/                     ← still combined (not yet split)
```

Resolution is selected at run time — no symlinks are created. Each launcher passes the chosen design directory to the toolchain (qml6 `-I` import path for QML, `slint-viewer -L design=…` for desktop Slint, `PICO_RES=…` env var for Pico builds).

## Implementations

### Qt (GPU + Qt5Effects)

```bash
qt/run.sh             # default 1024x600
qt/run.sh 1280x800    # any resolution available under design/qt/
qt/run.sh 1920x1080 -platform vncgl:size=1920x1080:port=5901
```

`qt/main.qml` is logic-only and does `import Design 1.0`, instantiating `MainWindow {}` directly. The launcher invokes `qml6 -I design/qt/<WxH> qt/main.qml`; the `Design/qmldir` committed inside each resolution dir resolves the module to that resolution's `MainWindow.ui.qml`.

### Qt-nogpu (CPU raster)

```bash
qt-nogpu/run.sh           # default 1280x800
qt-nogpu/run.sh 800x600
```

Same `import Design 1.0 + qml6 -I` pattern as `qt/`.

### Slint (desktop)

```bash
slint/run.sh             # default 1024x600
slint/run.sh 1920x1080
```

`slint/main.slint` imports its window via `import {MainWindow} from "@design/MainWindow.slint";`. The launcher invokes `slint-viewer -L design=<design/slint/WxH> slint/main.slint`.

### Pico (RP2040)

```bash
cd pico
cargo build --release --features pico                # default 320x240
PICO_RES=320x240 cargo build --release --features pico
```

`build.rs` reads `PICO_RES` and registers `design/slint/$PICO_RES/` as the slint `@design` library. `ui/main.slint` does `import {MainWindow} from "@design/MainWindow.slint";`. Runner is `elf2uf2-rs -d` — board must be in BOOTSEL.

### Pico2 (RP2350)

```bash
cd pico2
cargo build --release                                # default 320x240
PICO_RES=320x240 cargo build --release
```

Same pipeline as Pico (consumes the same `design/slint/$PICO_RES/`). Custom display driver in `src/picores28.rs`. Runner is `picotool load -u -v -x -t elf`.

### Flutter

```bash
cd flutter
flutter pub get
flutter run
```

Multi-platform Flutter app. **Not yet split into `design/flutter/`** — `lib/` still mixes generated and hand-written widgets.
